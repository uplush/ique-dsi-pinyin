# 趣音启动修复

v0.1.1 给神游 DSi 趣音（HNKC）的输入线程加了初始化检查。

## 原因与处理

本地白屏记录中，输入线程调用声音更新时，全局声音对象仍为 NULL。原函数接着读取对象偏移 `0xEC` 的成员，导致 ARM9 数据访问异常。对象的地址原本要等构造函数返回后才写入全局指针。

补丁在 `0x0201133c` 的更新入口读取全局指针 `0x020ece48`：为空时直接返回本次更新；非空时保留原有条件分支，调用原来的声音处理函数。后续轮次在对象就绪后自然恢复正常处理。

这是 64 字节的原位替换，不改变应用长度，不新增线程或内存分配，也不把整个输入线程关掉。应用内部相关摘要记录一起更新。参考汇编在 `src/sound_guard.S`。

这是一项针对已验证系统组件的应用侧兼容性补丁，不是完整的模拟器时序修复。此前尝试过调整全局取指时序，首次启动有效、第二次仍白屏，最终没有采用。

## 校验与升级

- 完整安装会校验全部五个 NAND 目标组件，并从原版生成新副本。
- `upgrade` 要求原有四个组件与 v0.1.0 一致、趣音与原版一致，然后只改趣音。
- 每个组件和补丁均校验 SHA-256；已升级、错误版本、混合版本会在生成输出前被拒绝。
- 等长文件替换保留原 FAT、目录项和文件末尾未使用的分配空间。升级测试中仅四个属于趣音文件的加密扇区发生变化。
- 回滚生成另一个新文件，校验结果与升级前逐字节一致；升级副本仍保留。

## 已验证的内容

机器码测试覆盖空对象／已就绪对象、两种输入状态、两个缓冲槽，共八种组合；另有四种延迟初始化用例，确认下一次更新仍能进入原来的处理函数。

Windows 图形界面测试连续完成三次趣音启动、返回菜单，触摸正常。Android 选对 NAND 后也已收到趣音可打开的确认，但没有完成相同的完整回归序列。此次测试不包含完整音乐播放、录音或真机验证。

发布包不包含完整趣音程序、NAND、BIOS、设备信息或个人资料。
